# Smart PPL: ตารางปรับตัวเมื่อข้ามวันเพราะปวดขา

สถานะ: รออนุมัติ · ขนาดงาน: โปรเจกต์ปานกลาง (โค้ด ~6 ไฟล์ + ฟังก์ชันใหม่ 1 ไฟล์ + เทสต์)

## เจตนา (why)

ผู้ใช้เล่น PPL แล้วปวดขาหนักมากหลังวัน Legs (ลุกเดินแทบไม่ไหว) จึงกดข้ามวันถัดไป แต่ตารางไม่ขยับตาม
วันขาถัดไปมาตามปฏิทินทั้งที่ยังไม่หายปวด ต้องข้ามต่ออีก สัปดาห์หนึ่งได้ฝึกจริงแค่ 3 วัน
ผู้ใช้ขอให้ "แอปรู้ว่าข้ามหลังเล่นขา แล้วตารางปรับเอง ไม่ยึดให้เล่นขาต่อ" โดยยึดหลักการออกกำลังกาย

## เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ห้ามเกิด

เป้าหมาย
- กดข้ามพร้อมระบุ "ปวดขา" แล้วตารางวันที่เหลือปรับให้อัตโนมัติ: ขาไม่ลงซ้ำตอนยังปวด ส่วนบนที่ไม่เจ็บยังได้เล่น
- ย้อนกลับได้ในปุ่มเดียว · ใช้ได้ทั้งตาราง PPL ของผู้ใช้และตารางที่ออกแบบให้ (3–6 วัน)

ไม่ใช่เป้าหมาย (ตัดออกโดยตั้งใจ)
- ไม่ถามอาการปวดทุกเช้า (แนวทาง C) · ไม่เปลี่ยนตารางเป็นคิวเรียงลำดับ (แนวทาง A)
- ไม่ปรับตัวเลขฐานของ PPL (เซ็ต/ครั้ง/ท่า) และไม่ใส่ช่วงปูพื้นปริมาณขา 1–2 สัปดาห์แรก (เสนอเป็นงานต่อได้)
- ไม่ปรับอัตโนมัติถ้าผู้ใช้ไม่ได้กดข้าม (เช่น Pull 2 + RDL ที่ห่างวัน Legs 2 วัน ยังเป็นไปตามตารางเดิม)
- ไม่แตะกติกา streak (ข้ามวันไม่ทำให้ streak ขาดอยู่แล้ว)

สิ่งที่ห้ามเกิด: แก้แม่แบบตาราง 7 วันของผู้ใช้เงียบๆ · ยัดสองเซสชันในวันเดียว · ย้ายวันขาให้เร็วขึ้น ·
ปรับวันที่ฝึกแล้ว/เริ่มฝึกแล้ว/ผ่านไปแล้ว · พูดเป็นคำแนะนำทางการแพทย์

## หลักฐาน (ตรวจกับ Europe PMC แล้ว ข้อความอ้างเฉพาะที่อยู่ในบทคัดย่อ)

| ข้อค้นพบ | ที่มา |
|---|---|
| ปวดสูงสุดวันที่ 2–3 หลังออกแรง · การออกแรงแบบลงช้า (eccentric) ปวดมากสุด โดยเฉพาะท่าใหม่/กลับมาเล่น | Clarkson 1992 (PMID 1569847, DOI 10.1249/00005768-199205000-00004) · Cheung 2003 (PMID 12617692, DOI 10.2165/00007256-200333020-00005) |
| หลังปวดหนัก ลดความหนัก/ปริมาณลง 1–2 วัน หรือเล่นกล้ามเนื้อส่วนอื่นแทน · ยืด ประคบเย็น อัลตราซาวด์ ไม่ช่วย · ออกแรงเบาช่วยได้ชั่วคราว | Cheung 2003 |
| เล่นถึงหมดแรงทำให้ฟื้นช้าลง 24–48 ชม. | Morán-Navarro 2017 (PMID 28965198, DOI 10.1007/s00421-017-3725-7) |
| ความถี่ต่อกลุ่มกล้ามเนื้อยืดหยุ่นได้เมื่อปริมาณรวมเท่ากัน (25 งาน) · งานปี 2016 เคยสรุป 2 ครั้ง/สัปดาห์ดีกว่า 1 ครั้ง | Schoenfeld 2019 (PMID 30558493, DOI 10.1080/02640414.2018.1555906) · 2016 (PMID 27102172) |
| ปวดรุนแรง + ปัสสาวะสีชา → ต้องพบแพทย์ (rhabdomyolysis พบน้อย) | Huerta-Alardín 2005 (PMID 15774072, DOI 10.1186/cc2978) |

ข้อจำกัดที่ต้องเขียนในแอปตรงๆ: ส่วนใหญ่ศึกษาผู้ชายหนุ่มสุขภาพดี ระยะสั้น · งานของ Clarkson ใช้ท่า eccentric สูงสุดที่แขน หนักกว่าวันขาในยิมมาก ·
ไม่มีงานใดทดสอบ "การจัดตารางใหม่หลังข้าม" โดยตรง กติกาข้างล่างเป็นการประยุกต์จากข้อมูลปวด/ฟื้นตัว ตัวเลขวันเป็นค่าที่ผมเลือก (ดูหัวข้อ "ที่ผมตัดสินใจเอง")

## แนวทางที่พิจารณา (ผู้ใช้เลือก B)

- A. คิวหมุนเวียน: ตารางเป็นลำดับเซสชัน ข้ามแล้วไม่ใช้เซสชันนั้น — ตรงที่สุด แต่รื้อสัปดาห์/streak/แชร์แผน/ซิงก์ (ทุกอย่างผูกกับวันในสัปดาห์ผ่าน `dayIdx`) เสี่ยงสูง
- **B. ตารางเดิม + แอปปรับทับรายวัน (เลือก):** แม่นยำพอ แก้น้อย ย้อนกลับได้ ไม่แตะแม่แบบ/แชร์/ซิงก์
- C. B + ถามอาการปวดทุกเช้า — แม่นกว่าแต่เพิ่มการกด ซึ่งผู้ใช้ไม่ต้องการ

## การออกแบบ (แนวทาง B)

### ข้อมูล (เก็บใน `logs[date]` ที่ซิงก์รายวันอยู่แล้ว → ไม่ต้องแก้ `merge.js`)

```
logs[S]  = { ..., skipped: true, why: 'sore' }            // วันที่กด "ปวดขา"
logs[X]  = { sets: {}, ..., adj: { as?: 0-6, drop?: [exerciseId...], via: 'YYYY-MM-DD(S)' } } // วันข้างหน้าที่ถูกปรับ
```
- `as` = ให้วัน X ใช้เซสชันของวัน (จันทร์=0) ในแม่แบบ · `drop` = ท่าที่ตัดออกจากวันนั้น · `via` = วันข้ามที่เป็นต้นเหตุ
- `sanitizeLog` ต้องตรวจ: `why` ต้องเป็น 'sore' และต้องมี `skipped` · `adj.as` เป็นจำนวนเต็ม 0–6 · `drop` เป็น string ≤20 ตัว ≤60 ตัวอักษร · `via` ตรงรูปแบบวันที่ · ค่าเสียให้ลบฟิลด์ ไม่ทิ้งทั้ง log
- ค่าที่คำนวณแล้วถูกเขียนลง log (ไม่คำนวณตอนแสดงผล) เพื่อไม่ให้การเปลี่ยนค่าคงที่ในเวอร์ชันหน้าไปเปลี่ยนสถานะ "พลาด" ของวันในอดีต

### ตัวเลือกวัน: `dayFor(s, date)` (ใหม่) → `{ day, src }`
`day = plan.days[adj.as ?? dayIdx(date)]` แล้วตัดท่าใน `adj.drop` · `src` = ดัชนีวันในแม่แบบที่ใช้จริง (ใช้ตอน `editDay`)
แทนการอ่าน `plan.days[dayIdx(...)]` ที่ `store.js` (`itemsFor`, `dayStatus`), `Today.jsx` (รวม `editDay(di)` ตอนสลับท่า ต้องใช้ `src`),
`Progress.jsx:229`, `Memory.jsx:94`, `review.js:88,102` — ตรวจว่า adherence/fatigue ไม่นับวันที่ย้าย/ตัดว่าพลาด

### ตัววางแผน `planSore(plan, logs, S)` (ฟังก์ชันบริสุทธิ์ใน `src/lib/resched.js`, ทดสอบด้วย Node)

นิยาม
- ท่า "ใช้ขา" = `byId[id].g` เป็น `legs` หรือ `full` (คาร์ดิโอเดิน/วิ่งไม่นับ)
- เซสชัน "ขาเป็นหลัก" = ท่าใช้ขา ≥ 40% ของท่าทั้งหมด (Legs & Abs, Lower) · ต่ำกว่านั้น = "ผสม" (Pull 2 + RDL, Full Body)
- `L` = วันล่าสุดก่อน S ที่ finished และมีเซ็ตที่ทำแล้วในท่าใช้ขา (หาจาก logs ไม่ดูแม่แบบ)
- `gate` = max(L+3, S+3) วัน (ไม่มี L = S+3) · ถ้ารายงานปวดซ้ำ gate เลื่อนตามวันรายงานล่าสุด (+3)
- ขอบเขต = วัน (S, S+7] ที่ยังไม่ผ่าน/ยังไม่เริ่มฝึก/ไม่ finished

ลำดับ
1. เซสชัน "ผสม" ที่ตกก่อน `gate` → ใส่ `drop` ตัดท่าใช้ขาออก (คงส่วนบนไว้ แสดงข้อความว่าตัดอะไร)
2. เซสชัน "ขาเป็นหลัก" ที่ตกก่อน `gate` (รวมของวัน S เอง) → ย้ายไปวันแรก X ≥ gate ในขอบเขตที่เป็นวันพัก/เดิน/เซสชันไม่ใช้ขา แล้วสลับเซสชันของ X มาที่วันที่ว่างลง (สลับ ไม่ซ้อน) · หาไม่ได้ → ตัดทิ้งสัปดาห์นั้น ไม่ทบ
3. ถ้าเซสชันของวัน S เองไม่ใช้ขา (เช่น Push 2) และมีวันเดิน/พักว่างหลัง S ในขอบเขต → ย้ายไปวันนั้น (ชดเชยเซสชันที่เสียไป) · ไม่แทนที่วันฝึกอื่น
4. คืนผลเป็นแผนที่ `date → adj` และข้อความสรุปเป็นรายการ (แสดงใน UI)

ตัวคงที่ (`RECOVER_DAYS=3`, `SORE_DAYS=3`, `LEG_SHARE=0.4`) อยู่บนสุดของไฟล์พร้อมคอมเมนต์อ้างหลักฐาน

คำนวณซ้ำได้ (idempotent): เมื่อเพิ่ม/ลบการข้ามแบบ "ปวดขา" ให้ล้าง `adj` ของวันที่ยังแก้ได้ แล้วไล่วางแผนใหม่ตามลำดับวันข้ามทุกครั้ง ·
`skipDay(date, false)` (ปุ่ม "กลับมาฝึกวันนี้") ล้าง `why` และ `adj` ที่ `via` = date

ตัวอย่างที่ต้องผ่านเป็นเทสต์
- PPL 5 วัน: พุธ Legs เสร็จ → พฤ. กด "ปวดขา" → gate = อา. · ศ. Pull 2 ไม่มี RDL · ส. (เดิม: เดิน) = Push 2 ชดเชย · อา. พัก
- 6 วัน PPL×2 (จ.–ส.): พุธ Legs → พฤ. ปวดขา → gate = อา. · ศ. Pull · ส. Push (ชดเชย) · อา. Legs (สลับกับ ส. ที่กลายเป็นพัก)

### UI
- `Today.jsx`: เมื่อ `done === 0` เพิ่มปุ่ม "ปวดขา — ข้ามและปรับตาราง" ข้างปุ่มเดิม ("เหนื่อยหรือไม่ว่าง" ไม่ปรับตาราง) · ใต้ปุ่มสำหรับวันที่ไม่ใช้ขา: "วันนี้ไม่ได้ใช้ขา ถ้าไหวลองเล่นเบาๆ ได้" (Cheung 2003)
- หลังกด: การ์ด "ข้ามวันนี้" แสดงสรุปการปรับ (เช่น "ศ. ตัด RDL · ส. Push 2 (ย้ายมาจาก พฤ.)") + ปุ่มย้อน · วันที่ถูกปรับมีป้าย "ปรับแล้ว" ในแถบสัปดาห์
- `Plan.jsx`: แม่แบบ 7 วันเหมือนเดิม เพิ่มแถบข้อความรายการปรับของสัปดาห์นี้ (อ่านอย่างเดียว)
- ความปลอดภัย: ตอนกด "ปวดขา" แสดงข้อความ "ปวดมากผิดปกติ ขาบวมตึง หรือปัสสาวะสีชา ให้ไปพบแพทย์" · เพิ่มบรรทัดเดียวกันใน `StopSigns`
- `Me.jsx` รายการแหล่งอ้างอิง: เพิ่มหัวข้อ "ปวดกล้ามเนื้อหลังเล่นขา" (ข้อค้นพบ + ข้อจำกัดข้างบน + DOI) ตามรูปแบบเดิม

### เทสต์ (`scripts/check.mjs` เพิ่มบล็อกเดียว ตามสไตล์เดิม)
ตัวอย่างข้างบน 2 กรณี · ตัวคงที่: ไม่มีวันที่มีสองเซสชัน · ไม่แตะวัน finished/เริ่มแล้ว/ผ่านแล้ว · ไม่ย้ายขาให้เร็วขึ้น · idempotent · undo กลับเท่าเดิม ·
sanitize ล้างค่า `why`/`adj` ที่เสีย · ตาราง generate ทุกชุด (3–6 วัน) ไม่ throw และรักษาคงที่ข้างต้น

## ที่ผมตัดสินใจเอง (ผู้ใช้ยังไม่ได้เห็นชอบทีละข้อ)
1. gate = 3 วันหลังเล่นขา และ 3 วันหลังรายงานปวด — ไม่มีงานวิจัยกำหนดตัวเลขนี้ เลือกให้เลยจุดปวดสูงสุด (วันที่ 2–3) และสอดคล้องกับที่ผู้ใช้เล่าว่าวันที่ 3 ก็ยังไม่หาย ปรับค่าได้ที่ตัวคงที่
2. เซสชัน "ขาเป็นหลัก" = ท่าใช้ขา ≥ 40% · ต่ำกว่านั้นตัดเฉพาะท่าขา
3. ชดเชยเซสชันส่วนบนที่ข้ามไปไว้วันเดิน/พักถัดไป · ขาที่หาที่ไม่ได้ในขอบเขต 7 วัน ตัดทิ้ง ไม่ทบ (ปริมาณรายสัปดาห์สำคัญกว่าความถี่ — Schoenfeld 2019)
4. ขอบเขตการปรับ = 7 วันหลังวันข้าม ไม่ใช่สัปดาห์ปฏิทิน เพื่อไม่ต้องมีกติกาข้ามสัปดาห์
5. ปุ่มข้ามแบบเดิมไม่ปรับตาราง (ไม่ใช่ทุกการข้ามเกิดจากปวดขา)
